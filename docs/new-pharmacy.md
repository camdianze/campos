# 새 약국 하나 들이기

처음부터 끝까지의 순서. 선유님이 약국을 방문해서 하는 일이다.

준비물: 노트북(발급 도구와 이 저장소가 있는 PC), 인터넷, 약국의 재고 설문지.

---

## 0. 미리 정할 것 — `site_id`

이 약국을 가리키는 **가명 코드**다. 한 번 정하면 바꾸지 않는다.

```
KH-0001, KH-0002, …
```

**약국 이름을 넣지 않는다.** 이 코드는 항생제 연구 제출 파일에도 쓰이고, 거기서 이름이 드러나면 가명이 아니게 된다. 어느 약국인지는 발급 대장(`license_issuance.label`)이 들고 있다.

---

## 1. 라이선스 발급 — 노트북

발급 도구(`campos-license-issuer`)로 코드를 만든다. 만료일은 계약대로.

나온 것 두 가지를 적어 둔다:

| | |
|---|---|
| 라이선스 코드 | `CAMPOS-XXXXXXXX-…` — 약국 PC에 입력할 것 |
| **일련번호** | 발급 대장의 행 번호. 다음 단계에서 쓴다 |

---

## 2. 서버에 등록 — Supabase SQL Editor

약국과 라이선스를 묶는다. **이걸 안 하면 다음 단계에서 토큰을 못 받는다.**

```sql
insert into public.site (site_id, label)
values ('KH-0002', '두 번째 약국')
on conflict (site_id) do nothing;

insert into public.license_issuance (serial, site_id, label, expires_at)
values (42, 'KH-0002', '두 번째 약국', '2027-10-01');
```

`42` 자리에 1단계의 일련번호를 넣는다.

> **갱신할 때도 한 줄씩 추가**한다. 일련번호는 발급할 때마다 새로 나오고 `site_id`는 그대로다 — 그래서 한 약국에 여러 줄이 쌓인다.

---

## 3. 설치 — 약국 PC

`CamPOS-stable-Setup.exe`를 들고 가서 실행한다 (USB로 가져가도 된다).

| 뜨는 것 | 할 일 |
|---|---|
| "Windows의 PC 보호" | **추가 정보 → 실행** (서명이 없어서 뜬다) |
| .NET 설치 | 기다림. 인터넷이 필요하고 한 번뿐이다 |

설치되면 `%LOCALAPPDATA%\CamPOS`에 들어가고 바탕화면에 바로가기가 생긴다.

> 인터넷이 아주 느린 곳이면 .NET Desktop Runtime 설치 파일을 미리 받아 가는 편이 낫다. 약 55MB이고, 한 번 깔면 이후 업데이트에는 필요 없다.

---

## 4. 활성화 — 라이선스 코드 하나

앱을 켜면 활성화 화면이 나온다. **1단계의 라이선스 코드를 입력**한다.

이때 뒤에서 일어나는 일:

```
앱 ──라이선스 코드──> register 함수
                       ├ 서명 확인
                       ├ 일련번호 → 2단계에서 넣은 줄 → site_id
                       └ 토큰 발급
앱 <──토큰───────────┘  DPAPI로 저장 (화면에 안 보임)
```

**동기화 토큰은 따로 입력하지 않는다.** 주소와 공개 키도 앱에 실려 있다.

인터넷이 안 되면 활성화만 되고 동기화는 설정되지 않는다 — **앱은 그대로 쓸 수 있고**, 나중에 7번에서 다시 하면 된다.

---

## 5. 초기 설정 — 시설과 첫 관리자

활성화 다음 화면이다. 약국 이름·주소 등과 **첫 Administrator 계정**을 만든다.

이 계정의 비밀번호는 약국이 정하게 한다. 선유님이 알 이유가 없다.

---

## 6. 데이터 넣기 — Data Center

Admin Dashboard → **Data Center**

1. **통화를 `៛`** 로 (설문지가 리엘로 적혀 있으면)
2. **① 제품 임포트** — 설문지 파일
3. 미리보기에서 **건수와 통화**를 확인하고 확정
4. **② 재고 임포트** — 같은 파일
5. **③ 사진** — 폴더가 있으면

> 설문지에 **낱개 가격**이 비어 있으면 그 제품은 박스로만 팔린다. 낱개로 팔 제품은 `loose_unit_price`를 채워야 한다 — 비워 두면 나중에 "낱개 판매가 안 된다"가 된다.

---

## 7. 확인

Admin Dashboard → **Data Center → SERVER SYNC**

| | |
|---|---|
| 주소·공개키 | 채워져 있어야 함 (앱이 넣은 것) |
| Device token | ●●●로 채워져 있어야 함 (4번에서 받은 것) |
| **Test Connection** | `Connected. The server knows this computer as KH-0002.` |

여기서 **`site_id`가 2단계에서 정한 것과 같은지** 꼭 보세요. 다르면 대장의 일련번호를 잘못 넣은 것이다.

그다음 **Synchronize** 한 번 → Supabase에서 [check.sql](../supabase/check.sql) 실행 → 제품 수가 맞는지.

### 토큰이 안 채워져 있으면

4번에서 인터넷이 안 됐거나 2단계를 빠뜨린 것이다.

```powershell
.\supabase\new-token.ps1 -SiteId KH-0002 -Label "약국 PC"
```

나온 토큰을 Data Center에 붙여넣고, 같이 나온 SQL을 Supabase에 넣는다. (2단계를 빠뜨린 거라면 그것부터 넣고 앱을 다시 켜는 쪽이 낫다.)

---

## 8. 영수증 설정

Admin Dashboard → **Receipt Settings**

약국 이름·주소·전화·VAT 번호·환율. **기본값이 비어 있다** — 적지 않으면 영수증에 안 나온다.

오른쪽 미리보기가 실제 종이와 같은 렌더러를 쓰므로, 거기 보이는 대로 인쇄된다.

---

## 9. 업데이트 채널

Admin Dashboard → **Updates** → 채널이 **`stable`** 인지 확인한다 (기본값).

먼저 확인해 줄 약국 한 곳만 `test`로 두고, 나머지는 전부 `stable`이다.

---

## 마지막으로

- 약국에 **바탕화면 바로가기**를 알려준다
- 관리자 비밀번호는 약국이 보관한다. 잊으면 복구 이메일이 필요하므로 **복구 이메일을 설정해 두는 것**이 좋다
- 선유님 기록에 남길 것: 약국 이름 · `site_id` · 일련번호 · 방문일
