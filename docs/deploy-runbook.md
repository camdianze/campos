# 배포 운영 매뉴얼

**읽는 사람: 선유님(운영자).** 이 문서는 약국에 주지 않는다.

여기 적힌 일은 전부 약국이 할 수 없는 일이다. 라이선스를 만드는 도구와 개인키는
다른 저장소(`campos-license-issuer`)에 있고 약국 PC에 가지 않으며, 토큰 발급과
새 버전 올리기는 Supabase 대시보드 권한이 있어야 한다. 약국이 읽을 것은
[pharmacy-guide.md](pharmacy-guide.md) 쪽이다.

새 약국을 처음부터 들이는 순서는 [new-pharmacy.md](new-pharmacy.md)에 있다.
이 문서는 **이미 v1.26을 쓰고 있는 약국을 v2로 옮기는 일**과, 그 뒤로 계속
반복되는 일(USB 재설치, 서버 업데이트)을 다룬다.

> **먼저 읽을 것: [지금 안 되는 것](#지금-안-되는-것).** 현장에서 걸리는 것이
> 거기 있고, 아래 절차는 그걸 피해 가도록 짜여 있다.

## 1. 라이선스와 토큰 발급

### 무엇이 몇 개인가

| | 무엇 | 어디에 저장되나 | 복원하면 |
|---|---|---|---|
| 라이선스 코드 | 앱을 열 수 있게 한다 | `%APPDATA%\CamdiansRX\license.dat` (**파일**) | 살아남는다 |
| 동기화 토큰 | 이 PC를 서버에 알린다 | 데이터베이스 안 `App_Setting` | **사라진다** |

둘이 저장되는 자리가 다르다는 것이 아래 2번 순서를 정한다.

### ① 코드 만들기 — 노트북

발급 도구로 코드를 만든다. 만료일은 계약대로. 나오는 것 두 가지를 적어 둔다.

| | |
|---|---|
| 라이선스 코드 | 약국 PC에 입력할 것 |
| **일련번호** | 발급 대장의 행 번호. 다음 단계에서 쓴다 |

### ② 서버에 묶기 — Supabase SQL Editor

**이걸 빠뜨리면 활성화는 되지만 토큰을 못 받는다.**

```sql
insert into public.site (site_id, label)
values ('KH-0002', '두 번째 약국')
on conflict (site_id) do nothing;

insert into public.license_issuance (serial, site_id, label, expires_at)
values (42, 'KH-0002', '두 번째 약국', '2027-10-01');
```

`42` 자리에 ①의 일련번호. 갱신할 때도 줄을 **추가**한다 — 일련번호는 매번 새로
나오고 `site_id`는 그대로라, 한 약국에 여러 줄이 쌓이는 것이 정상이다.

`site_id`에 **약국 이름을 넣지 않는다.** 이 코드는 항생제 연구 제출 파일에도
실리고, 거기서 이름이 드러나면 가명이 아니게 된다.

### ③ 토큰 — 보통은 저절로 받는다

약국 PC에서 라이선스 코드를 넣으면 앱이 `register` 함수를 불러 토큰을 받아
DPAPI로 저장한다. **토큰을 손으로 입력하지 않는다.**

인터넷이 안 되거나 ②를 빠뜨렸으면 토큰만 비어 있다. 앱은 그대로 쓸 수 있고,
나중에 아래 방법으로 넣으면 된다.

### ④ 토큰을 손으로 발급해야 할 때

②를 빠뜨렸던 경우라면 **②부터 넣고 약국 PC에서 다시 활성화하는 쪽이 낫다.**
그게 안 되는 상황(이미 활성화가 끝났다, 복원으로 토큰이 날아갔다)에서만 아래를 쓴다.

```powershell
.\supabase\new-token.ps1 -SiteId KH-0002 -Label "약국 PC"
```

화면에 나오는 것:

1. **토큰 원본** — 이 창에만 보인다. 비밀번호 관리자에 저장한다
2. **SQL 두 줄** — Supabase SQL Editor에 붙여넣는다 (서버는 SHA-256만 갖는다)

토큰 원본을 약국 PC의 **Data Center → SERVER SYNC → Device token**에 붙여넣고
Save → Test Connection.

> 토큰 원본이 SQL에 들어가지 않는 이유: SQL Editor의 쿼리 기록은 지우기 번거롭고,
> 지웠는지 확인할 방법도 없다.

## 2. v1.26 약국에 v2 설치 — 백업 복원 순서

**순서가 전부다.** 복원은 데이터베이스 파일을 통째로 덮어쓰므로
(`File.Copy(..., overwrite: true)`), 그 안에 있는 동기화 토큰과 설정이 백업 쪽
값으로 바뀐다. v1 백업에는 그 키들이 아예 없어서 **빈 값이 된다.**

### 준비물

- USB: `CamdiansRX-stable-Setup.exe`, .NET Desktop Runtime 오프라인 설치 파일
  (4번 참고)
- 새로 발급한 라이선스 코드와 일련번호
- 인터넷 (활성화와 토큰 발급에 필요)

### 순서

| | 하는 일 | 확인할 것 |
|---|---|---|
| 1 | v1.26에서 **백업 파일 만들기** | 파일 크기가 0이 아닌지 |
| 2 | `%APPDATA%\PharmaPOS` **폴더를 통째로 USB에 복사** | `.db`, `-wal`, `-shm` 세 파일이 다 있는지 |
| 3 | v1.26 앱을 **완전히 종료**하고 옛 프로그램과 `%APPDATA%\PharmaPOS`를 지운다 | 작업 관리자에 남은 프로세스가 없는지 |
| 4 | v2 설치 → 첫 실행 | 활성화 화면이 뜨는지 |
| 5 | **활성화** — 라이선스 코드 입력 | 토큰이 자동으로 들어온다 |
| 6 | **초기 설정** — 임시 시설·임시 관리자 | 어차피 복원으로 지워진다. 아무 값이나 |
| 7 | 로그인 → Data Center → **Restore** → 1번의 백업 파일 | 재시작된다 |
| 8 | **v1 관리자 계정**으로 로그인 | 6번의 임시 계정은 이제 없다 |
| 9 | **토큰을 다시 넣는다** (1-④) | ← **이 단계를 빼먹으면 동기화가 안 된다** |
| 10 | 3번 동기화 확인 | |

**2번은 1번이 있어도 한다.** 백업 파일이 깨져 있으면 돌아갈 곳이 폴더 사본뿐이다.
되돌릴 때는 v2를 지우고, USB의 `PharmaPOS` 폴더를 `%APPDATA%`에 되돌려 놓고,
v1.26 설치 파일을 다시 깐다.

### 9번이 필요한 이유

복원 뒤 `App_Setting`은 v1 백업의 내용이다. 그래서:

| 설정 | 복원 뒤 | 결과 |
|---|---|---|
| `sync.token` | 없음 | **동기화 안 됨 — 다시 넣어야 한다** |
| `sync.url`, `sync.key` | 없음 | 앱에 실린 기본값을 쓴다. 문제없다 |
| `sync.auto` | 없음 | 기본값 **켜짐**. 문제없다 |
| `sync.pharmacyData` | 없음 | 기본값 **켜짐**. 약국이 거절했다면 다시 꺼야 한다 |
| `update.channel` | 없음 | 기본값 **stable**. 문제없다 |
| `license.dat` | 파일이라 영향 없음 | 그대로 |

9번을 하고 나면 Data Center에 토큰이 `●●●`로 차 있어야 한다.

### 폴더를 안 지우는 길(자동 이전)은 지금 쓰지 않는다

`%APPDATA%\PharmaPOS`를 남겨 두면 첫 실행 때 자동으로 복사해 온다. 데이터는
제대로 오지만 **옛 `license.dat`까지 따라와서 활성화 화면이 뜨지 않는다.** 그러면
새 라이선스가 들어가지 않고, `register`를 부르지 않으니 토큰도 안 생긴다.

고쳐야 할 것이고([아래](#지금-안-되는-것)), 고쳐지기 전에는 위의 "지우고 설치"
순서를 쓴다.

## 3. 서버 동기화 확인

### 약국 PC에서

**Admin Dashboard → Data Center → SERVER SYNC**

| 보는 것 | 정상 |
|---|---|
| 주소·공개 키 | 채워져 있다 (앱이 넣은 값) |
| Device token | `●●●`로 차 있다 |
| **Test Connection** | `Connected. The server knows this computer as KH-0002.` |
| 마지막 전송 / 대기 건수 | 전송 뒤 대기가 0으로 떨어진다 |

**`site_id`가 1-②에서 정한 것과 같은지 반드시 본다.** 다르면 대장의 일련번호를
잘못 넣은 것이고, 그 약국의 자료가 남의 `site_id`로 들어가고 있다는 뜻이다.

그다음 **Synchronize**를 한 번 누른다.

### 서버에서

Supabase SQL Editor에서 [check.sql](../supabase/check.sql)을 실행한다.

| 증상 | 뜻 |
|---|---|
| `마지막 전송`이 방금으로 안 바뀜 | 서버에 닿지 않았다 — 주소·토큰·회선 |
| `마지막 전송 상태`가 `failed` | 사유가 `sync_batch.error`에 그대로 있다 |
| 표 행 수가 0 | 토큰은 맞는데 보낼 것이 없거나, 약국 데이터 전송이 꺼져 있다 |
| 같은 묶음을 두 번 보냈는데 행이 늘어남 | 키가 잘못 걸린 것. `(site_id, 원본 ID)`라 그럴 일은 없어야 한다 |

시각이 **프놈펜과 한국 둘 다** 찍혀 나온다. 프놈펜이 두 시간 느리므로, 한국 시계로
읽으면 방금 보낸 것이 두 시간 전 것처럼 보인다.

`check.sql`의 두 번째 쿼리는 약국별 최근 7일 기능 사용이다. 설치 직후에 한 번
돌려서 **0으로 남은 기능**을 본다 — 안 쓴 것인지, 못 찾은 것인지, 눌렀는데 실패한
것인지는 `실패` 칸이 가른다.

### 조용히 멈추는 경우

자동 동기화는 30분마다 돌고 **실패해도 아무 말을 하지 않는다.** 회선이 한 시간
끊긴 약국에 한 시간 동안 대화상자를 띄울 수 없어서다. 그래서 보는 자리가 둘이다:

- 약국 화면: 상단 바의 동기화 경고 배지 (꺼 둔 것과 못 보내는 것을 다르게 말한다)
- 서버: `check.sql`의 `마지막 전송`

대기 건수가 0이면 아무리 오래됐어도 경고하지 않는다 — 조용한 연휴는 고장이 아니다.

## 4. USB로 배포하기

### USB에 담을 것

```
USB/
  CamdiansRX-stable-Setup.exe          ← 설치 파일 (약 7 MB)
  windowsdesktop-runtime-10.0.15-win-x64.exe  ← .NET 데스크톱 런타임 (57 MB)
  pharmacy-guide.pdf                   ← 약국에 주는 안내 (선택)
```

**설치 파일은 `deploy.ps1`이 만든 `releases/` 폴더에서 가져온다.** 그 폴더의
`*.nupkg`와 `RELEASES-*`는 서버 업데이트용이라 USB에는 필요 없다 — Setup.exe
하나면 설치된다.

### .NET 런타임을 같이 담는 이유

패키지를 프레임워크 의존으로 만들기 때문에(자체포함이면 64MB가 되어 Supabase
무료 요금제의 50MB 한도를 넘는다), 설치 프로그램이 런타임을 Microsoft에서
받아 온다. **첫 설치 때 한 번, 인터넷이 필요하다.**

약국 회선이 느리면 55MB를 받는 동안 설치가 멈춰 있는다. 미리 받아서 USB에 담고
**설치 전에 먼저 실행**하면 그 대기가 없어진다. 한 번 깔면 이후 업데이트에는
필요 없다.

받는 주소는 고정 링크 하나다. 늘 그 시점의 최신 10.0 패치로 넘어간다.

```
https://aka.ms/dotnet/10.0/windowsdesktop-runtime-win-x64.exe
```

PowerShell에서 받을 때는 `-UseBasicParsing`을 붙인다. 없으면 Internet Explorer
엔진 초기화를 물으려다 비대화형 세션에서 그냥 실패한다.

```powershell
Invoke-WebRequest -Uri "https://aka.ms/dotnet/10.0/windowsdesktop-runtime-win-x64.exe" `
    -OutFile "windowsdesktop-runtime-win-x64.exe" -UseBasicParsing
```

**받은 뒤 서명을 확인한다.** 약국 PC에서 실행될 설치 파일이고, 링크 한 번으로
받은 바이너리다.

```powershell
Get-AuthenticodeSignature .\windowsdesktop-runtime-win-x64.exe |
    Select-Object Status, @{n='Signer';e={$_.SignerCertificate.Subject}}
```

`Status`가 `Valid`이고 `Signer`가 `CN=.NET, O=Microsoft Corporation`이어야 한다.

끝자리(patch)는 달라도 된다 — 10.0 안에서는 앱이 더 높은 패치로 올라가 실행된다.
2026-11-21 기준 받아지는 것은 **10.0.15**이고,
SHA256은 `E61B030C1673EDFA3C0844502EFF83198C46AF9E7DF70DFC6E2EFC5B11EA513A`다.

### 설치할 때 뜨는 것

| 뜨는 것 | 할 일 |
|---|---|
| "Windows의 PC 보호" | **추가 정보 → 실행** |
| .NET 설치 | 기다림 (런타임을 미리 깔았으면 안 뜬다) |

코드 서명 인증서가 없어서 SmartScreen 경고가 뜬다. 인증서가 생기면
[deploy.ps1](../deploy.ps1)의 `$signParams` 두 줄 주석을 풀면 된다. **설치된 뒤의
자동 업데이트에는 이 경고가 영향을 주지 않는다** — 경고는 사람이 exe를 실행할
때만 뜬다.

### 재설치할 때

같은 Setup.exe를 다시 실행하면 된다. 데이터(`%APPDATA%\CamdiansRX`)는 설치
위치(`%LOCALAPPDATA%\CamdiansRX`)와 다른 폴더라 **지워지지 않는다.**

## 5. 서버를 통한 업데이트

약국은 아무것도 하지 않는다. 앱이 시작할 때 한 번 조용히 확인하고, 내려받고,
**앱을 닫을 때 설치한다.** 묻지도 알리지도 않는다 — 계산대에서 물어볼 질문이
아니고, 느린 회선이 앱 열리는 것을 붙잡아서도 안 된다.

### 올리는 순서

```powershell
.\deploy.ps1 -Version 2.2 -Channel test
```

이 스크립트가 하는 일: 버전 올림 → **테스트 실행(실패하면 중단)** → 게시 →
Velopack 패키지 → 올릴 파일 목록 출력. **업로드는 하지 않는다.**

1. 출력된 파일을 Supabase → Storage → `releases` → **`test/`** 에 올린다
2. 본인 PC와 약국 한 곳에서 확인한다
3. 확인되면 **같은 파일**을 `stable/` 에 올린다

**`RELEASES-<채널>` 파일을 반드시 포함한다.** 그것이 목록이고, 없으면 아무도 새
버전을 보지 못한다.

### 업로드 권한이 저장소에도 앱에도 없는 이유

업로드 열쇠를 앱에 넣으면 약국 PC 수백 대에 뿌려진다. 그중 한 대만 뜯겨도 모든
약국에 아무 버전이나 보낼 수 있다. 읽기만 열어 두면 최악의 경우가 "남이 우리
설치 파일을 내려받는 것"으로 끝나고, 그 파일은 어차피 약국에 나가는 것이다.

그래서 업로드는 **대시보드에서 사람이** 한다. 버킷을 처음 만드는 절차는
[releases-bucket.md](../supabase/releases-bucket.md)에 있다.

### 잘못 올렸을 때

**되돌릴 수 없다.** 이미 받아 간 PC가 있기 때문이다. 수습은 **더 높은 번호의
수정판**을 올리는 것뿐이다. 그래서 `test/`를 먼저 거친다.

### 전화로 확인할 것

업데이트가 약국 몰래 일어나므로, "어제부터 안 된다"는 연락이 오면 읽을 것이
있어야 한다. `%APPDATA%\CamdiansRX\update-log.txt` — 일반 텍스트이고, 앱이 안
열려도 읽히며, 전화로 불러 줄 수 있다.

화면의 버전은 Admin Dashboard → Updates, 또는 어느 화면에서나 좌하단의
`CamdiansRX v.2.1`.

| | 무엇 | 지금의 대처 |
|---|---|---|
| 1 | **복원이 동기화 토큰을 지운다** | 2번 순서의 9단계(토큰 재발급)를 반드시 한다 |
| 2 | **자동 이전이 옛 `license.dat`를 가져온다** → 활성화 화면이 안 뜬다 | 자동 이전을 쓰지 않는다. 폴더를 지우고 설치 |
| 3 | **복원 파일 검증이 약하다** — 표가 하나라도 있으면 통과 | 복원할 파일을 눈으로 확인한다. 엉뚱한 `.db`를 골라도 막히지 않는다 |
| 4 | Data Center에 "Connect to server" 단추가 없다 | 토큰은 `new-token.ps1`로만 다시 넣는다 |
| 5 | 라이선스 발급 도구가 서버에 자동 등록하지 못한다 (`issue` 함수 미배포, `issuer_secret`·`cloud.json` 미설정) | 1-②의 SQL을 손으로 넣는다 |
| 6 | Edge Function 4개가 재배포되지 않았다 | 오류 문구가 옛 형태로 나올 수 있다. 서버 동작에는 지장 없음 |
| 7 | 자동 업데이트를 실제로 받아 본 적이 없다 | 약국에 가기 전에 본인 PC에서 `test` 채널로 한 번 받아 본다 |
| 8 | Supabase 무료 요금제가 쉬면 프로젝트가 멈춘 적이 있다 | 방문 전날 대시보드에서 깨어 있는지 본다 |
| 9 | `campos_metrics` 비밀번호가 화면 공유로 노출됐다 | 교체하거나 `alter role campos_metrics nologin;` |

1~4는 모두 **"복원"이라는 한 가지 일**에서 나온다. 그 네 가지가 고쳐지면 2번
순서는 9단계가 사라지고, 자동 이전 쪽 길도 쓸 수 있게 된다.
